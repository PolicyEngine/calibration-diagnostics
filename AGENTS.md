# AI assistant guidance

- When an AI assistant launches the dashboard, it must give the development server process read access to a collector calibration tree store. The release and staging calibration views read only that store: the tree manifest, each build's copies of its original files, each country's `releases.json` copy and the copies of the staging runs' files. This is required for every local preview, not an optional configuration step.
  - Pass the store's read-write token as `BLOB_READ_WRITE_TOKEN`. The Vercel project's Preview environment names the collector's staging store; its token is a credential Anthony handles.
  - Load the credential from the approved secret source and pass it in the same command environment that starts `make dev` or `bun run dev`. Never print or commit its value.
  - Before providing a Staging preview URL, request `/api/microcosm/staging/runs` for the selected country and confirm that the JSON response is `available: true` and lists runs. Checking only the HTTP status is insufficient, because the route answers HTTP 200 with `available: false` when the store holds no copies of the country's staging runs. Treat a 502 and any `available: false` response as a failed launch.
- When investigating a discrepant Microcosm calibration target, follow [the shared investigation workflow](docs/ai/workflows/investigate-microcosm-target.md) and its linked role-specific reviews.
- Before starting the application for Cross-dataset work, configure exactly one DIR or URL artifact location for each country you will use, as described in [the Cross-dataset application configuration](docs/cross-dataset-api.md#configure-the-application).
- Adding a Microcosm country is one entry in `packages/calibration-tree/src/countries.ts` in PolicyEngine/microcosm-collector, released as a new `@policyengine/calibration-tree` npm version, then a pull request here raising `frontend/package.json`'s pinned version; pages are gated by the registration's capabilities and the release artifact's `country` block, never by country code (see [the spec-driven countries note](docs/spec-driven-countries.md)).
- The calibration tree package (`@policyengine/calibration-tree`: the tree builder, its types and readers, the Blob I/O and the publisher) has its only source in PolicyEngine/microcosm-collector. Change it there and raise its version; this repository installs a published version from npm and keeps no copy. The release history is the one exception: its Blob store module (`frontend/lib/microcosm/release-history-store.ts`) and the script that writes to it (`frontend/scripts/release-history.ts`) belong in this repository, so leave them here and do not flag them as copies of the package (calibration-diagnostics#224).
